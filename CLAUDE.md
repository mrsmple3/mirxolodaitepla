# Проект: сайт «Мир холода и тепла»

Статический сайт частного мастера по установке и обслуживанию кондиционеров и котлов.
Единственная метрика успеха: звонок или сообщение в мессенджер. Всё остальное — средство.

## Команды

- `npm run dev` — дев-сервер
- `npm run build` — сборка в `./dist`
- `npm run verify` — полный прогон: build → html → links → schema → lh

Отдельные проверки:
- `npm run html` — html-validate по `dist/**/*.html`
- `npm run links` — linkinator по `dist` (0 битых ссылок)
- `npm run schema` — `scripts/check-schema.mjs`: парсит весь JSON-LD в `dist`, проверяет обязательные поля и совпадение NAP с `src/data/business.ts`
- `npm run lh` — Lighthouse (mobile) по собранному `dist`

**Пороги, ниже которых работа не считается сделанной:**
Performance ≥ 95, SEO = 100, Accessibility ≥ 95, Best Practices ≥ 95. LCP < 2.0s, CLS < 0.05.

## Жёсткие правила

- **Zero client-side JS по умолчанию.** Любая директива `client:*` — только после моего явного разрешения. Меню, аккордеон, табы — на `<details>`, `:target`, `:has()`, CSS. Не на JS.
  - **Единственное разрешённое исключение — тег Google Ads (gtag.js, `AW-18405480299`)** для отслеживания конверсий: базовый тег в `<head>` и скрипт отправки конверсии по клику на `tel:`, Telegram и WhatsApp в конце `<body>`, оба в `src/layouts/Base.astro`, оба `is:inline`. Любые другие внешние скрипты (метрики, чаты, виджеты, пиксели) по-прежнему запрещены. `npm run schema` пропускает только эти три `<script>`.
  - Этот тег ставит сторонние cookie `doubleclick.net`, поэтому Lighthouse Best Practices ниже 95. Это известное следствие исключения, а не дефект вёрстки.
- Никаких CSS-фреймворков, UI-китов, иконочных пакетов, Google Fonts по CDN. Шрифты — локальные `.woff2` в `/public/fonts`, `font-display: swap`, `preload` только для display-начертания.
- **Контакты живут только в `src/data/business.ts`.** Телефон, мессенджеры, адрес, часы, зона выезда, цены — оттуда. Захардкоженный номер в разметке = баг.
- **NAP-консистентность:** название, адрес и телефон в JSON-LD обязаны посимвольно совпадать с видимым текстом страницы. Это проверяет `npm run schema`.
- **Не выдумывай факты о мастере.** Опыт, сертификаты, отзывы, кейсы, цены, названия брендов — только из данных, которые я дал. Нет данных → `TODO:` в `src/data/`, а не правдоподобный текст.
- **Ни одной страницы ради объёма.** Новая страница создаётся, только если у неё есть собственный поисковый интент и ≥300 слов уникального смысла. Страницы вида «услуга + район» по шаблону с подстановкой города — **запрещены** (Google, scaled content abuse, март 2026).
- Изображения: `<picture>` с AVIF + WebP + fallback, явные `width`/`height`, `loading="lazy"` везде кроме hero, `fetchpriority="high"` у hero.
- Телефон на мобильном — `<a href="tel:">`, всегда в зоне большого пальца, всегда виден.

## Стиль кода

- Компоненты `.astro`. Стили — в `<style>` компонента; общие токены — `src/styles/tokens.css`.
- CSS: логические свойства (`padding-inline`, `margin-block`), `clamp()` для типографики и отступов, каскадные слои (`@layer tokens, base, layout, components`). Никаких `!important`.
- Разметка семантическая: один `<h1>` на страницу, `<main>`, `<nav>`, `<address>`, корректная иерархия заголовков.
- Обязательный «пол качества»: видимый `:focus-visible`, `prefers-reduced-motion`, контраст ≥ 4.5:1, работа с клавиатуры.

## Порядок работы

- Перед реализацией страницы сверься со `SPEC.md`. Если задача противоречит SPEC — остановись и спроси, не решай сам.
- После правки шаблонов, данных или схемы: `npm run verify`. **Показывай вывод команды, а не утверждение «готово».**
- В конце сессии обнови `STATE.md`: что сделано, что сломано, что следующее.
