# SPEC — сайт «Мир холода и тепла», Ташкент

Спецификация статического сайта частного мастера по кондиционерам и котлам.
Документ самодостаточен: по нему сайт собирается без доступа к переписке, в которой он
родился. Если реализация противоречит SPEC — останавливаемся и спрашиваем заказчика,
а не решаем на месте.

**Единственная метрика успеха: звонок на +998 90 904 50 10 или сообщение в Telegram.**
Всё остальное на сайте — средство.

---

## 1. Что ещё нужно получить от мастера

Раздел стоит первым намеренно. Всё перечисленное отсутствует в данных, а значит —
**отсутствует на сайте**. Придумывать вместо этого правдоподобный текст запрещено.

### Блокирует запуск

| Что | Зачем |
|---|---|
| Домен | canonical, `url` в JSON-LD, sitemap, Open Graph |
| Фамилия Ровшана | `Person` в разметке статей, страница доверия |
| Telegram-username | Пока ссылка строится по номеру: `https://t.me/+998909045010` |

### Блокирует страницу `/ustanovka-kotla/`

**Есть ли у Ровшана допуск на работы с газовым оборудованием?**

- **Есть** — страница делается как описано в §4.6.
- **Нет** — страница «установка газового котла» в этом виде не существует. Вместо неё
  узкая страница про обвязку отопительного контура и подключение к системе отопления,
  с прямым указанием, что газовую часть подключает специализированная организация.
  Заголовок и весь семантический слой страницы меняются.

Решение принимает заказчик. Разработчик не выбирает этот вариант самостоятельно и не
пишет «монтаж газовых котлов», пока ответ не получен.

### Сильнее всего поднимет конверсию (не блокирует, но меняет результат)

- **Фотографии реальных объектов.** Сейчас их нет, и это главная слабость сайта.
  Нужны: наружный блок на фасаде, аккуратная трасса в коробе, манометрический коллектор
  на работе, котельная после обвязки. 8–12 штук достаточно.
- **Портрет Ровшана.** Лицо на странице доверия работает сильнее любого текста.
- **Сканы допусков и удостоверений**, особенно по газу.
- **Число лет в профессии.** «Многолетний опыт» на сайт не идёт — это ровно та вода,
  которую запрещает `CLAUDE.md`. Нужна цифра, иначе про стаж не пишем вообще.
- **Бренды**, с которыми мастер работает по кондиционерам и по котлам.

### Чего нет и что поэтому запрещено писать

Опыт в годах, допуски и сертификаты, бренды, цены, отзывы, фотографии, гарантия,
юридический статус, договоры, чеки, безнал.

Ни одно из этих слов не появляется на сайте, пока данные не получены. Отдельно:
**слово «гарантия» на сайте не встречается ни разу** — формальной гарантии нет,
а обещать её нельзя.

### На чём в итоге стоит сайт

Классических опор доверия у нас нет. Остаются три, и вокруг них строится весь макет:

1. **Имя и город** — Ровшан, Ташкент. Не безликое ООО.
2. **Круглосуточная доступность** — «открыт в момент запроса».
3. **Цена по фото за 10 минут** — заменяет отсутствующий прайс.

Четвёртая опора создаётся текстом: конкретика ремесла вместо прилагательных.
Не «качественный монтаж», а вальцовка, опрессовка азотом, вакуумирование, уклон дренажа.
Это одновременно и доверие, и весь информационный трафик. Если из текстов уйдёт
конкретика, у сайта не останется ни одного аргумента.

## 3. Модель данных `src/data/business.ts`

```ts
/** Маркер отсутствующих данных. Не должен попадать в разметку. */
type Todo = `TODO: ${string}`;
type Maybe<T> = T | Todo;

export const isTodo = (v: unknown): v is Todo =>
  typeof v === 'string' && v.startsWith('TODO:');

export interface Business {
  name: string;                    // 'Мир холода и тепла'
  master: {
    firstName: string;             // 'Ровшан'
    lastName: Maybe<string>;
    experienceYears: Maybe<number>;
    certifications: string[];      // пусто = не упоминаем
    gasClearance: Maybe<boolean>;  // решает судьбу /ustanovka-kotla/
  };
  phone: { raw: string; display: string };
  telegram: { url: string; label: string };
  address: {
    addressLocality: string;       // 'Ташкент'
    addressCountry: string;        // 'UZ'
    hasOffice: false;
  };
  areaServed: string[];            // ['Ташкент']
  openingHours: { allDay: true };
  season: 'summer' | 'winter';
  services: Service[];
  photos: { works: Photo[]; portrait: Maybe<Photo> };
  url: Maybe<string>;
  sameAs: string[];                // карточки в картах, когда появятся
}
```

Правила:

- **`raw` и `display` — разные поля.** `raw` идёт в `href="tel:"` и в `telephone` JSON-LD,
  `display` — в видимый текст. Формат каждого из них не меняется нигде на сайте.
- **Цены.** Поле `price` у `Service` необязательное и **на страницы не выводится**.
  Так решение «показать цены» позже не потребует переписывания шаблонов.
- **`Todo` ломает сборку.** Компонент, получивший `Todo` в видимый текст или в JSON-LD,
  бросает исключение на этапе билда. Забытая заглушка не должна тихо уехать в прод.
- **`season`** переключается вручную двумя правками в год. С мая по сентябрь `'summer'`,
  с ноября по март `'winter'`. Значение читается на сборке, никакого JS в браузере.

## 4. Карта страниц

Страница существует, только если у неё есть собственный поисковый интент и ≥300 слов
уникального смысла. **Страниц вида «услуга + район Ташкента» не будет** — это шаблонное
размножение, за которое Google снимает трафик.

Title ≤ 60 символов, description 140–160. Город — в title каждой коммерческой страницы.

### 4.1 `/` — главная

- **Интент:** навигационный и общий коммерческий — «мастер по кондиционерам Ташкент».
- **title:** Кондиционеры и котлы в Ташкенте — монтаж и ремонт
- **description:** Ровшан ставит, чистит и ремонтирует кондиционеры и котлы в Ташкенте. Работаю сам, круглосуточно. Пришлите фото в Telegram — назову цену за 10 минут.
- **h1:** Установка и обслуживание кондиционеров и котлов в Ташкенте
- **JSON-LD:** `HVACBusiness`

**Первый экран** отвечает на «приедешь ли ты ко мне и сколько это будет стоить»,
а не рассказывает миссию. Состав, сверху вниз:

1. h1 с городом.
2. Одна строка о том, кто это: мастер Ровшан, работает сам, выезд по Ташкенту.
3. Оффер вместо цены: пришлите фото места установки в Telegram — назову цену за 10 минут.
4. Две кнопки: «Позвонить +998 90 904 50 10» и «Написать в Telegram». Обе — в зоне
   большого пальца на ширине 360px, видны без прокрутки.
5. Круглосуточно, без выходных — отдельной заметной строкой.

**Сезонный блок** (управляется `season`): летом первым идёт монтаж и обслуживание
кондиционеров, зимой — котлы. Меняется порядок и акцент первого экрана, а не содержание сайта.

**Обязательные блоки ниже:**

- Четыре услуги карточками со ссылками на свои страницы.
- Три блока возражений (§5).
- Как проходит работа: от звонка до включения — 4–5 шагов обычными словами.
- Финальный блок связи.

**Запрещено на главной:** форма заявки, отзывы, цифры цен, «наша команда», «широкий спектр
услуг», «индивидуальный подход», «качественно и в срок», стоковые фотографии, счётчики
и виджеты, слово «гарантия».

### 4.8 Обязательный каркас каждой страницы услуги

Одинаковый для 4.2–4.7, порядок не меняется:

1. **Что входит в работу, по шагам, с деталями ремесла.** Не список из трёх пунктов,
   а реальный порядок действий.
2. **Что НЕ входит и за что берётся отдельно.** Прямо и без эвфемизмов.
3. **От чего зависит цена.** Без цифр: этаж, длина трассы, тип стены, высотные работы,
   штробление, зимний комплект. Заканчивается оффером «фото в Telegram — цена за 10 минут».
4. **Сколько занимает по времени.**
5. **2–3 ошибки самодеятельного или дешёвого монтажа и чем они заканчиваются.**
   Конкретно: непровакуумированная трасса, трасса без уклона, перетянутая вальцовка.
6. **Блок связи:** телефон и Telegram. Не форма-заглушка.

- **Интент:** брендовый, страница доверия.

процесса: как идёт работа от звонка до включения, чем работаю, за что не берусь и почему,

Слоты под фото объектов и портрет заложены в макет и заполняются, когда фото появятся.
**Пока их нет — это самая слабая страница сайта, и это надо понимать.**
Стоковые фотографии вместо них — запрещены.

## 5. Возражения — три блока на главной

Каждый блок — абзац конкретики, а не заголовок-лозунг.

1. **«В магазине монтаж бесплатный».** Что реально входит в такой монтаж, какая длина
   трассы в него заложена и за что доплачивают уже на месте.
2. **«Непонятно, сколько выйдет в итоге».** От чего зависит цена и как узнать её до выезда:
   фото места установки в Telegram — ответ за 10 минут. Прямое следствие решения
   не публиковать прайс.
3. **«Страшно за стену и за соседей снизу».** Как идёт работа по шагам: разметка и поиск
   проводки, трасса, вальцовка, опрессовка, вакуумирование, уклон дренажа.

Первый и третий одновременно закрывают возражение и работают на информационные запросы.

## 6. JSON-LD

- **Все страницы:** `HVACBusiness` — самый конкретный подходящий тип, не общий
  `LocalBusiness`. Поля: `@id`, `name`, `telephone`, `address`, `areaServed`,
  `openingHoursSpecification`, `image`, `url`, `sameAs`.
  - `address` — `PostalAddress` с `addressLocality: 'Ташкент'` и `addressCountry: 'UZ'`,
    **без `streetAddress`**: офиса нет, это service-area business.
  - `openingHoursSpecification` — все семь дней, `opens: '00:00'`, `closes: '23:59'`.
- **Страницы услуг:** `Service` с `provider` по `@id` и `areaServed`.
- **`offers` не размечаем.** Цен нет, а `Offer` без цены — мусор в разметке.
  Осознанное отклонение от исходного техзадания; причина зафиксирована здесь.
- **`FAQPage`** — только если вопросы и ответы реально видны на странице.
- **`BreadcrumbList`** — на всех внутренних страницах.
- **`BlogPosting`** — на статьях.
- **`aggregateRating` не размечаем никогда.** Своих отзывов нет, а размечать
  собственные отзывы на своём сайте нельзя в принципе.

**NAP-консистентность.** `name`, `telephone` и `addressLocality` в JSON-LD обязаны
посимвольно совпадать с видимым текстом страницы и со значениями в `business.ts`.
Проверяется автоматически (§8).

**Локаль.** `lang="ru"`, гео — Узбекистан. Структура URL готова принять узбекскую версию
в `/uz/` без переезда, но на этом этапе она не делается.

## 7. Контент-план

1. **Какой кондиционер выбрать по площади комнаты** — 07/09/12/18, поправки на сторону
   света, этаж, площадь остекления, технику в комнате.
2. **Почему течёт кондиционер и что сделать до приезда мастера** — дренаж, уклон трассы,
   засор, обмерзание испарителя.
3. **Кондиционер не морозит: что проверить самому за пять минут.**
4. **Почему падает давление в котле** — подпитка, расширительный бак, течи в системе.
5. **Чем плох «бесплатный монтаж» из магазина** — вальцовка, опрессовка, вакуумирование,
   длина трассы. Работает на возражение №1.

Правила: первый абзац отвечает на вопрос из заголовка, остальное — детали. Никакой воды
и «в современном мире». Числа, диапазоны и коды ошибок — только реальные.

**Технические факты ремесла писать можно** — это отраслевое знание, а не биография мастера.
**Всё, что относится лично к Ровшану, — только из `business.ts`.** Не хватает данных для
статьи — статья не пишется, вопрос уходит заказчику.

- проверяет, что телефон везде записан в одном формате и что `href="tel:"` использует `raw`;
- падает, если в разметку или в видимый текст попал `TODO:`.

**Пол качества, не обсуждается:** видимый `:focus-visible`, полная проходимость с клавиатуры,
`prefers-reduced-motion`, контраст ≥ 4.5:1, один `<h1>` на страницу, корректная иерархия
заголовков, `<main>`, `<nav>`, `<address>`, skip-link.

**Изображения:** `<picture>` с AVIF + WebP + fallback, явные `width`/`height`,
`loading="lazy"` везде кроме hero, `fetchpriority="high"` у hero.

**Zero client-side JS.** Ни одной директивы `client:*`. Меню, аккордеоны, табы — на
`<details>`, `:target`, `:has()`, CSS. Ни одного внешнего запроса из HTML: шрифты локальные
`.woff2` в `/public/fonts`, никаких CDN, Google Fonts и виджетов.

## 11. Дизайн-система — «Манометрический коллектор»

Выбрано на шаге 2 из трёх направлений. Метафора — коллектор, который мастер вешает
на блок первым делом: белый циферблат, риски лимба, синий порт низкого давления,
красный высокого, латунные фитинги.

Направление выбрано не за красоту, а по совпадению с задачей. У сайта нет ни цен,
ни отзывов, ни фотографий — единственный доступный аргумент это демонстрация точности.
Оформление, подающее текст как показания прибора, усиливает ровно тот аргумент,
который есть.

### 11.1 Палитра

Все значения проверены на контраст к фону-циферблату `#F4F6F7`.

| Токен | Значение | Роль | Контраст |
|---|---|---|---|
| `--c-dial` | `#F4F6F7` | фон страницы | — |
| `--c-surface` | `#FFFFFF` | карточки, шапка | — |
| `--c-graphite` | `#191E23` | основной текст, подвал | 15.5:1 |
| `--c-muted` | `#3D464F` | вторичный текст | 8.9:1 |
| `--c-low` | `#0B5AA6` | порт низкого давления — холод | 6.4:1 |
| `--c-high` | `#B3261E` | порт высокого давления — тепло | 6.0:1 |
| `--c-brass` | `#A8832C` | фитинги: риски, кромки | 3.3:1 |
| `--c-rule` | `#C9D2D8` | хайрлайны | декор |

**Сезон переставляет полюс.** `data-season` на `<html>` берётся из `business.season`;
летом акцент `--c-low`, зимой `--c-high`. Переключение на сборке, в браузер не уходит
ни байта скрипта.

### 11.2 Типографика

Роли перевёрнуты намеренно: заголовки набирает текстовая гарнитура, а моноширинная
работает приборным слоем.

| Роль | Гарнитура | Начертания | Вес файла |
|---|---|---|---|
| Заголовки и текст | Golos Text | 400, 700 | 21.6 КБ |
| Приборный слой: цифры, часы, телефон, подписи | Martian Mono | 500 | 7.6 КБ |

Обе OFL, кириллица родная, лежат локально в `public/fonts`, подмножество
кириллица + латиница + пунктуация. **Итого 29.2 КБ** против 52 КБ у тех же гарнитур
с Google Fonts — разница за счёт собственного сабсеттинга. `preload` только у
`golos-text-700.woff2`: им набран `h1`, он же LCP-элемент.

Вариативные начертания рассмотрены и отклонены: один variable-файл Golos Text
на веса 400–700 весит 58 КБ против 37 КБ у двух статических. Сайту нужны ровно два веса.

### 11.3 Сигнатурный элемент

**Риски приборного лимба** (`.scale`) — граница каждой секции. Два
`repeating-linear-gradient`: мелкая риска через 8 px графитом, крупная через 40 px
латунью. Ноль элементов в DOM, ноль картинок, ноль запросов. Других разделителей
на сайте нет. Вертикальный ритм кратен 8, поэтому риски совпадают с базовой линией.

### 11.4 Правила, без которых направление станет шаблоном

Сине-красная пара — палитра любого шаблона про кондиционеры. Удерживают только правила:

1. Цвет занимает не больше нескольких процентов площади: кромки, риски, одна кнопка.
2. Один акцент на экран. Синий и красный не встречаются вместе — их разводит сезон.
3. Латунь никогда не набирает текст (3.3:1). Только линии и кромки.
4. Моноширинная гарнитура не набирает заголовки. Только цифры, часы, телефон, подписи.
5. Ни одной залитой цветом панели.

### 11.5 Полоса вызова

Телефон обязан быть в зоне большого пальца и виден всегда (§8). На ширине < 48rem
внизу висит фиксированная полоса с двумя кнопками — «Позвонить» и Telegram.
`position: fixed`, в поток не входит, CLS не даёт; `body` получает нижний отступ,
чтобы полоса не накрывала подвал. На десктопе полоса скрыта, телефон живёт в шапке.

Поэтому кнопки первого экрана на мобильном не дублируются: те же два действия
постоянно на экране. На десктопе кнопки в первом экране есть.

### 11.6 Второй проход: упаковка, фон и скроллителлинг

Добавлено по правке заказчика 21.08.2026: «сайт выглядит как статья — текст,
текст и текст». Диагноз верный. Первый проход дал систему цвета, шрифта и меры,
но не дал **формы**: почти каждая страница была одной колонкой абзацев с
заголовками. Второй проход не меняет ни направление, ни палитру — он достраивает
уровень, которого не было.

**Что появилось.**

| Приём | Где | Зачем |
|---|---|---|
| Манометр | первый экран главной, от 48rem | Фотографий нет и не будет скоро (§2). Визуальный якорь приходится рисовать — берётся предмет, давший имя системе |
| Фон-прибор | все страницы | Лимб с рисками, разметочная сетка, обход стрелки, две промывки. Градиенты и маски: ноль картинок, ноль запросов |
| Показания | первый экран | Три строки вместо трёх абзацев про надёжность. Ни одна не придумана — всё сказано словами ниже |
| Двухколонные возражения | главная | Вопрос слева, ответ справа. Одной колонкой это и читалось сплошным текстом |
| Трасса ступеней | главная, `/o-mastere/` | Номера-риски на вертикальной линии, линия дорисовывается по прокрутке |
| Нумерация разделов | страницы услуг, `/kontakty/` | Разделы опознаются раньше, чем прочитан заголовок |
| Приборные маркеры списков | услуги, `/kontakty/`, `/o-mastere/` | Латунная галка — «входит», риска — «отдельно», номер — порядок работ |
| Знак в шапке и подвале | все страницы | Берётся из `scripts/brand/marks.mjs` — не копия, а тот же источник, что у фавиконок |
| Липкий блок связи | услуги и статьи, от 75rem | Справа от меры текста пустовала треть экрана. Туда ушёл телефон |
| Шкала прочитанного | все страницы | Стрелка по верхней кромке, привязана к позиции прокрутки |
| Появление блоков | все страницы | `animation-timeline: view()`, диапазон закрыт на 38–42% входа |

**Ноль JS остался нулём.** Всё сделано на scroll-driven animations и на CSS.
Скроллом управляет композитор, главный поток не участвует — TBT не растёт.

**Страховка.** Каждое правило, ставящее `opacity: 0`, лежит внутри
`@supports (animation-timeline: view())` **и** внутри
`prefers-reduced-motion: no-preference`. Браузер без поддержки и человек,
выключивший анимации, видят полностью собранную страницу. Скрытого текста
не остаётся ни в одном случае — это проверено замером computed-стилей.

**Что подвинулось в §11.4.** Правила 2, 3, 4 не тронуты. Правило 5 («ни одной
залитой цветом панели») соблюдено: `.panel` белая, работают кромка и тень.
Правило 1 («цвет не больше нескольких процентов площади») теперь читается
буквально: фон-прибор занимает весь экран, но его насыщенность — 4–8% акцента
в промывках и 8.5% графита в линиях. Это фактура бумаги, а не заливка. Если
считать это нарушением буквы правила — скажите, промывки снимаются одной
строкой в `--c-wash`.

**Цена по метрикам — ноль.** Lighthouse после правки: Performance 100 на всех
пятнадцати страницах, LCP 1.2–1.4 s, CLS ≤ 0.024 при пороге 0.05. Ни одна
анимация не трогает геометрию: только `opacity` и `transform`. Заголовок
первого экрана — LCP-элемент, и прозрачность ему не назначается: Chrome не
засчитывает отрисовку элемента с `opacity: 0`, и появление ушло бы в метрику
задержкой.

**Найденный при этом дефект сборки.** lightningcss, минификатор Astro по
умолчанию, сворачивал `animation-timeline` внутрь шортката `animation`:
`.reveal{animation:linear both reveal-rise view()}`. Спецификация такого
шортката не знает, объявление становилось невалидным целиком, и **все**
скролл-анимации молча выключались. Вёрстка при этом выглядела исправной —
ровно потому, что каждое правило написано со страховкой. Поймано замером
`getComputedStyle`, а не глазами. Минификатор переключён на esbuild в
`astro.config.mjs`, там же разбор.

**Третий найденный дефект — прозрачность текста.** Первая версия появления
блоков делала `opacity: 0 → 1`. На таймлайне `view()` это не доля секунды:
блок ниже сгиба стоит в начальном кадре всё время, пока до него не долистали,
то есть текст там по-настоящему нечитаем. axe внутри Lighthouse это и поймал —
контраст 1.13 при норме 4.5 на `/blog/besplatnyy-montazh-iz-magazina/`,
Accessibility 96. Прозрачность убрана отовсюду, где есть текст: блоки приходят
сдвигом, карточки — сдвигом с масштабом, номера ступеней — масштабом.
`opacity` осталась у одного элемента — рисок лимба, где текста нет.
После правки Accessibility 100 на всех пятнадцати страницах.

### 11.7 Отклонение от §4.1

§4.1 требует «четыре услуги карточками». После исключения `/ustanovka-kotla/`
(нет ответа про допуск) собираемых услуг осталось пять. Показаны все пять:
спрятать котлы летом — значит спрятать половину бизнеса. Порядок задаёт сезон.
